# First Region — Stylized Isometric Diorama Runtime Prototype

## Why this prototype exists

On 2026-10-04, the project owner supplied a visual target: a bright, toy-like/storybook 3D isometric landscape with a blue-roofed castle, a river and stone bridge, clustered cottages, cultivated fields, a windmill, rocks and dense green woodland. The current PIE image showed a largely empty green plane, edge-on Paper2D props and an unreadably small, leaf-shaped mage.

The target is a navigable game scene, not a single painted map image. The region layout therefore needs real world-space forms, paths and landmarks that remain usable with the existing server-authoritative character and movement systems.

## Repository implementation

`AAetherDevelopmentWorldActor` now assembles a development diorama from Unreal Engine's built-in BasicShapes at runtime. It adds:

- soft color patches and low rolling terrain;
- a winding river with layered banks and a highlight strip;
- two connected road routes and a raised stone bridge;
- a round village plaza, fountain, cottages, service buildings, market stalls and lanterns;
- three fenced crop plots with rows of crops;
- a multi-tower castle, curtain walls, gate, courtyard, garden and blue roofs;
- a perimeter forest with broadleaf, pine and flowering tree variations;
- a windmill, watchtower, ruins and rock formations.

Repeated river/road sections, tree foliage, crop rows, fence rails, bridge posts and castle crenellations are grouped into runtime instanced-mesh components by mesh, color material and collision behavior to keep the blockout practical to render.

The default playable mage is now assembled from separate 3D body, head, robe, arms, hands, legs, boots, hat, staff and orb pieces. This replaces the crude one-piece triangular sprite fallback. Authored Paper2D profiles remain available; a profile configured as the primary presentation can still take precedence.

The fixed isometric camera starts farther back and supports a wide zoom range so that the village, bridge and castle can be read together. WASD movement, jump, character identity, replication and server authority are unchanged.

## Asset and truth boundary

This is an **in-repository runtime blockout/prototype**, not the final production art depicted by the reference. Its pieces use engine primitive meshes and flat color materials; it does not yet provide handcrafted meshes, material textures, authored animation, level dressing, final lighting or a saved production `.umap`.

No `.uasset` or `.umap` is fabricated. The scene is generated by source code when the development world starts. It is intended to replace the empty/basic presentation and establish composition and scale before production asset replacement.

## Local Unreal acceptance still required

This checkout has no Unreal Engine installation, so UHT/UBT, PIE and visual review have not been run here. After synchronizing the branch on the UE 5.8 PC:

1. Close the Unreal Editor before compiling.
2. Build `AgeOfAetherEditor Win64 Development` with the project's UE 5.8 installation.
3. Open the project and the first-region/development map.
4. Run PIE; verify the castle, bridge, farmland and forest are visible from the gameplay camera.
5. Check that roads and bridge are traversable, houses/towers do not cover the spawn, and the mage reads as a humanoid at default zoom.
6. Test camera zoom, then review Output Log, collision and frame time.
7. Send a PIE screenshot back for camera/layout tuning before replacing the blockout pieces with production art.

Do not mark the visual/runtime gate complete until those local checks pass.
