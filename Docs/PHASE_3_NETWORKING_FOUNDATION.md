## Architecture

Age of Aether uses Unreal's client/server networking model. The server is authoritative and clients request operations; authoritative state is replicated back to clients. This matches Unreal Engine 5.8's documented networking architecture.

The implementation deliberately avoids making the client authoritative.

## Implemented

### Protocol contract

FAetherProtocolVersion defines a versioned protocol with major/minor values.

Compatibility is currently major-version based:
- same major = compatible;
- different major = incompatible.

Current() centralizes the active protocol version.

### Request/response contract

FAetherNetworkRequest contains:
- request ID;
- request type;
- protocol version.

FAetherNetworkResponse contains:
- request ID;
- result code;
- server protocol version;
- authoritative state revision.

Current request types:
- Heartbeat;
- QueryAuthoritativeState.

Current result codes:
- Accepted;
- InvalidProtocol;
- InvalidRequest;
- ServerUnavailable.

### Authoritative state

AAetherNetworkGameState owns replicated network state:
- protocol version;
- authoritative state revision.

Only the server may advance the revision.

### Request path

AAetherNetworkPlayerController is the client-owned request endpoint.

Flow:

Client
→ SendNetworkRequest
→ ServerSubmitRequest
→ protocol/request validation
→ authoritative server state access
→ mutation when appropriate
→ ClientReceiveResponse
→ client-side response event

Using PlayerController for the request RPC is intentional because it is owned by the corresponding client connection.

### Replay/order protection

The server stores the last processed request ID for the controller and rejects request IDs that are zero or not greater than the last processed request.

This is a first protection layer against replayed or stale requests. It is not a replacement for later authentication, rate limiting, anti-cheat or transaction idempotency systems.

### Network GameMode

AAetherNetworkGameMode wires AAetherNetworkGameState and AAetherNetworkPlayerController.

DefaultGame.ini selects the network GameMode as the global default.

## Security boundary

The server never accepts client-provided authoritative state, state revision, result, currency/item state, or gameplay mutation.

The request contains only an operation request and protocol metadata. The response is generated by the server.

## Replication strategy

The project is intentionally not enabling a custom Replication Graph at this phase.

Unreal 5.8 provides the generic replication system, Replication Graph and Iris. Replication Graph is intended for scaling replicated actors, while Iris provides a newer replication system alongside the generic system.

For the current foundation, generic replication is sufficient. A scale-specific replication strategy will be introduced only when profiling and world population justify it.

## Required local validation

The following must eventually be executed in Unreal Engine 5.8.1:

1. Generate/update project files.
2. Compile AgeOfAetherEditor.
3. Run Unreal Header Tool successfully.
4. Launch the Editor.
5. Start a listen/server PIE session.
6. Start at least one client.
7. Confirm the client receives replicated AAetherNetworkGameState.
8. Confirm protocol version is visible on the client.
9. Send a Heartbeat request.
10. Confirm the server advances the authoritative revision.
11. Confirm the client receives the response.
12. Send QueryAuthoritativeState.
13. Confirm the response contains the current authoritative revision.
14. Attempt an incompatible protocol request and confirm rejection.
15. Attempt a stale/replayed request ID and confirm rejection.
16. Run AgeOfAether.Networking.* automation tests.
17. Repeat with Unreal network emulation.

Epic recommends network emulation because perfect local connectivity does not expose many real-world latency and packet-loss problems; its UE 5.8 documentation specifically describes testing with latency and packet loss.

For later dedicated-server work, Unreal's dedicated-server model also follows the authoritative server/client architecture used here.
